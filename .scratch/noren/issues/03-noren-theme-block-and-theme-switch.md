# 03: The Noren Theme block, the Theme switch, and its contrast proof

**What to build:** A Consumer sets `data-theme="noren"` on the html element, or on any ancestor, and every Component under it renders in Noren: Washi and Paper surfaces, Cat text, Lantern primary, Cedar secondary, cloth Tabs on a Cedar Rail, underlined fields, flat 4px Buttons, a Rail on the Dialog instead of the arch, an Old wall overlay, Broth highlights, and the lantern glow on popups. Without the attribute, Ridgeline is unchanged. In Storybook a Theme toolbar switches the canvas between the two, and the Tokens Story proves every Noren pair meets WCAG. 2026-10-06: Landed on branch `noren-03-noren-theme-block-and-theme-switch`. Motion duration is the one Token it leaves out on purpose: declared there, it would sit after the reduced-motion media query and beat its 0ms. The header comment now describes two Themes. `.storybook/preview.ts` is `preview.tsx` and carries a `theme` toolbar global (Ridgeline, Noren), `initialGlobals.theme: "ridgeline"`, and a decorator that sets `data-theme="noren"` on the html element for Noren and removes the attribute for Ridgeline. Both fonts imports stay. `src/docs/Tokens.stories.tsx` gains a `Noren` Story and a `ThemeSwitch` Story, and its contrast loops moved into `expectContrastIn(root)`, which the Ridgeline Story calls with the body and the Noren Story with its wrapper.

How the Noren Story fails on an undeclared Token. Computed style cannot tell, because a Token the block forgets inherits Ridgeline's value through the wrapper. The Story walks `document.styleSheets` for the rule whose `selectorText` contains `data-theme="noren"` and reads each name from that rule's own `style`. The list it checks is `themeTokens`, every colour, shadow, radius, width, space, padding, font, font size, and label style Token in the file, without motion duration.

Where the `:root` override lands. A rule on `:root` alone does not reach inside a `data-theme="noren"` wrapper: the wrapper's own block re-declares the Token on the wrapper, and that beats the inherited value. The spec's "beats both" holds with the attribute on the html element, where `:root` and the Theme block target the same element and the Consumer's rule wins on specificity. The ThemeSwitch Story proves it that way: it puts the attribute on `document.documentElement`, sets an inline `--kui-primary` there, reads the Button outside the wrapper as the override under Noren, removes the attribute and reads it again as the override under Ridgeline, then cleans up before asserting. It also asserts that the Button inside the wrapper stays Lantern through all of that. A Consumer who themes a subtree and wants an override to reach it writes the override as `:root, [data-theme] { --kui-primary: ...; }`. Tickets 05 and 06 should read this before the Vite check and the Getting started page.

Two things the board shows that no Token reaches, left as they are rather than adding a Theme selector to component CSS. The outline Button's fill is transparent in `Button.css`, so under Noren it shows Washi inside its 2px Cat edge, not the board's Paper. The Dialog title keeps `font-style: italic` from `Dialog.css`, so under Noren the browser synthesizes an oblique Shippori Mincho B1; the title is Cat and in the display face as story 20 asks, but slanted. Both are recorded in the spec's Further notes.
