# 09: Dialog

**What to build:** A Consumer assembles a modal Dialog from parts. Opening traps focus inside, Escape and overlay click close it, focus returns to the trigger, and screen readers announce the title and description.

**Blocked by:** 01 (Scaffold, Tokens, and Button end to end)

**Status:** ready-for-agent

- [x] Composite component built on the Radix Dialog Primitive, exposed as a namespace with root, trigger, content, title, description, and close parts; the overlay and portal are handled inside the content part
- [x] Controlled and uncontrolled via open, defaultOpen, onOpenChange
- [x] Focus moves into the dialog on open, is trapped while open, and returns to the trigger on close; body scroll is locked while open
- [x] Escape and overlay click close; the close part renders an accessible close button with the inline close icon
- [x] Title and description are wired to the dialog's labelling attributes; a Story shows how to hide the title visually while keeping it for assistive technology
- [x] Open and close transitions are removed under reduced motion
- [x] Stories for Default, with a form inside, with a long scrolling body, and a controlled example; a play function opens with the keyboard, asserts focus is inside, presses Escape, asserts focus returned to the trigger
- [x] axe passes on every Story; lint, typecheck, build pass

## Comments

2026-09-22: Implemented in da7e36d (the six parts, the stylesheet, eight Stories, a changeset) and 0d56470 (code review fixes). Verified locally: lint, typecheck, 81 Story tests in Chromium with axe (8 of them Dialog), and build all pass, both Themes were checked by eye in Storybook, and the reduced motion path was driven by hand in Chromium with the media feature emulated. Decisions worth knowing. The parts are Root, Trigger, Content, Title, Description, and Close, and Content renders the portal and the overlay itself, so a modal takes no wrapper. Like Tabs and unlike Tooltip and RadioGroup, Dialog does not own its state: Radix writes data-state "open" or "closed" onto the trigger, the overlay, and the panel, which are already the kit's words. Root renders no element, so it takes no ref and no class name, and its prop doc says so. Trigger always slots the element it is given, the way Tooltip takes its trigger, because the look of a trigger belongs to the Consumer. Close is the other way round: on its own it renders the kit's icon button in the corner, named "Close", and `asChild` swaps in a Consumer's element, which the kit then leaves unstyled since its own corner styling would wreck a Button. The panel itself does not scroll. Its children scroll in an inner viewport element, so the close button, which is positioned against the panel, stays in the corner however far a long body scrolls; the Long Body Story scrolls to the last clause and clicks the button to prove it. Every Story puts the Close part last in the panel, so the first field gets focus in a form dialog and the icon button is the last Tab stop. Radix returns focus by focusing the trigger explicitly rather than by restoring the previously focused element, so a controlled dialog with no Trigger part leaves focus on the body when it closes. The Controlled Story therefore keeps a trigger and closes from application code instead, and a triggerless dialog is a candidate for a later ticket. The open and close animations carry different names because Radix tells them apart by name alone, and it holds the panel in the DOM until the closing one ends. Under reduced motion the stylesheet drops both animations outright rather than leaning on the 0ms motion Token, since a zero-length animation still has to reach its end event before Radix will unmount the panel; no Story covers that path, the same gap Switch and Tooltip have. The scrim is a new `--kui-overlay` Token, one value for both Themes, because ADR 0001 rules out a hard-coded colour and the spec's Token roles had no overlay role. The body scroll lock is asserted through the body's own computed overflow, since a Story cannot raise the trusted wheel or key event a user would scroll a page with. Radix warns in development when a panel has no Description, so every Story ships one. Radix's onEscapeKeyDown, onPointerDownOutside, modal, and forceMount are not exposed: Escape and the overlay close the dialog, and everything is modal. Kit-wide, the class-name join is now in seven Components and verify-build.mjs gained two more lines, so the shared helper and the derived build check from ticket 06's notes are still open candidates.
