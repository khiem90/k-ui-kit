The Getting started page covers install, the one stylesheet import, server components, a sign-up form built from TextField, Select, Checkbox, and Button that a hidden Story also renders live and tests, the Theme attribute, and a table of every Token in both Themes. `pnpm smoke` (scripts/smoke-test.mjs) packs the kit, scaffolds a fresh Next.js App Router app and a fresh Vite app in a temporary folder, installs the tarball, builds both, and drives them in Chromium: every Component renders from a server component with no client directive in the app and answers to input, the Vite bundle keeps Button and TextField and drops the other eight, the stylesheet ships, and both Themes apply through the attribute and the system preference. Its first run found two defects, both fixed here rather than filed. A server component could not render Dialog.Root, Select.Root, Tabs.Root, or RadioGroup.Root, because the whole package was one client module and a server component cannot reach into a client reference; the Next.js build failed on prerender. And a Vite build kept all ten Components when the app imported two, because forwardRef and createContext calls in one file cannot be dropped. The build now emits one file per source file: each Component file keeps its own client directive, relative imports in shipped source end in .js, and src/index.ts stays free of the directive and assembles the composite namespaces. ADR 0003 records the choice, the build verifier enforces the shape and imports the entry in Node, and the public API is unchanged. Verified locally: lint, typecheck, and build pass, 107 Story tests pass in Chromium with axe, the static Storybook builds, and the smoke test passed both against reused apps and from a clean scaffold. Decisions worth knowing. Every Story now imports from the public entry, the seam the spec names. The form Story lives in src/docs with the `!dev` tag, so it runs as a test without a sidebar entry; its JSX is duplicated in the page's code block on purpose, because a Canvas cannot show a wrapper's body. remark-gfm is a devDependency so the page's Token table parses. The smoke test runs by hand; wiring it into the Release workflow before the publish step is a candidate, as is the shared visually hidden utility and the labels prop noted in earlier tickets.
