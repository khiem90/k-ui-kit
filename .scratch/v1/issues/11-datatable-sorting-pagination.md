# 11: DataTable with sorting and pagination

**What to build:** A Consumer passes typed column definitions and a data array and gets a real HTML table with a caption, sortable headers, and pagination. Screen reader users navigate it as a table and hear the current sort.

**Blocked by:** 01 (Scaffold, Tokens, and Button end to end)

**Status:** ready-for-agent

- [x] Component is generic over the row type; column definitions use the TanStack Table shape and the column definition type is re-exported from the package entry
- [x] Props in this ticket: columns, data, getRowId, caption, sortable, pageSize
- [x] Renders a native table element with a caption, header cells with scope, and body rows; no grid role
- [x] When sortable, header cells contain a button that cycles ascending, descending, and none; the sorted column exposes aria-sort; a visual indicator uses the inline chevron icon
- [x] When pageSize is set, previous and next controls built from Button and a page status line are rendered; controls are disabled at the bounds; the status is announced politely on change
- [x] Forwards ref to the table, accepts className on the root, spreads rest props onto the table
- [x] Stories for Default, sortable, paginated, sortable and paginated, and a wide table that scrolls horizontally; a play function activates a header with the keyboard and asserts row order and aria-sort, then pages forward and asserts the visible rows
- [x] axe passes on every Story; lint, typecheck, build pass

## Comments

2026-09-23: Implemented in 64341cc (the Component, the stylesheet, six Stories, a changeset) and 20c6f67 (code review fixes). Verified locally: lint, typecheck, 100 Story tests in Chromium with axe (6 of them DataTable), and build all pass, and both Themes, the sort button's focus ring, the wide table's scrolling region, and the generated props table were checked by eye in Storybook. Decisions worth knowing. The engine is TanStack Table 9.2.4, whose API is feature-based: the kit registers sorting and paging with `tableFeatures` and calls `useTable`, and every TanStack type takes the feature set as its first type parameter. So `ColumnDef` reaches the entry as an alias bound to the kit's feature set rather than a bare re-export, since a bare one would make a Consumer name the kit's internals; object literals in the TanStack shape type-check against it, and a pre-bound column helper is a candidate for later. Four sort functions are registered (alphanumeric, basic, datetime, text) because v9 only resolves the ones a table registers, and their names are valid `sortFn` strings in a column definition. Every column starts ascending, one column sorts at a time, and the cycle is ascending, descending, unsorted; TanStack's default would start numbers descending. The chevron shows only on the sorted column, and on hover or focus of an unsorted header pointing the way the next activation sorts, after the review found that a muted chevron on every unsorted header left unsorted and ascending different by colour alone. Paging is one controlled pagination state handed straight to TanStack; a sort returns to the first page (TanStack's auto reset), a new page size starts from the first page, and no page size maps to Infinity, which TanStack documents as one page holding every row. A table wider than its container scrolls sideways, and while it does the scroll container is a region named by the caption and a Tab stop, measured with a ResizeObserver so a table that fits adds no Tab stop; the Tab stop is what axe's scrollable-region-focusable rule requires and what lets a keyboard user scroll. Cells stay on one line so a wide table scrolls rather than cramming its columns, and a column of prose wraps again with one rule. The sort button's focus ring sits inside its cell (outline-offset -2px, where the kit's other rings use 2px) because the scroll container clips an outset ring at the table's edges. Previous and Next use native `disabled` as the ticket asks, so when Next becomes disabled under keyboard focus on reaching the last page, focus drops to the body; `aria-disabled` with focus kept is a candidate. The two Button labels and the page status are English only; label props for other languages are a candidate. The Stories annotate their meta as `Meta<DataTableProps<Member>>` instead of the kit's `satisfies` form, because StoryObj can only infer a generic Component's constraint. Kit-wide, the class-name join is now in nine Components and verify-build.mjs gained three lines, so the shared helper and the derived build check from earlier tickets are still open candidates. Unrelated to this ticket, the Select Long List Story failed in two of three full suite runs and passed every time alone, so it is timing-sensitive under parallel load; it is flagged as a separate task.
