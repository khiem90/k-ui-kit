# 10: Select

**What to build:** A Consumer assembles a Select from parts, sized to line up with TextField. Keyboard users open it, arrow through options, jump by typing, and pick with Enter.

**Blocked by:** 01 (Scaffold, Tokens, and Button end to end)

**Status:** ready-for-agent

- [x] Composite component built on the Radix Select Primitive, exposed as a namespace with root, trigger, content, item, and group parts; the trigger renders the inline chevron icon, items render the inline check icon when selected
- [x] Controlled and uncontrolled via value, defaultValue, onValueChange; placeholder supported
- [x] Sizes sm, md, lg on the trigger match TextField heights
- [x] Arrow keys move through options, typeahead jumps to a match, Enter selects, Escape closes; disabled items are skipped
- [x] Trigger accepts an accessible name via a visible label or aria-label; the listbox and option roles are exposed
- [x] Parts forward refs, accept className, spread rest props
- [x] Stories for Default, each size, with groups, with a disabled item, with a placeholder, and a controlled example; a play function opens with the keyboard, arrows, selects, and asserts the trigger text and callback
- [x] axe passes on every Story; lint, typecheck, build pass

## Comments

2026-09-23: Implemented in 311a7e7 (the five parts, the stylesheet, thirteen Stories, a changeset) and ce375a8 (code review fixes). Verified locally: lint, typecheck, 94 Story tests in Chromium with axe (13 of them Select), and build all pass, and both Themes, the open list, the size row beside a TextField, the groups, the long list with its scroll button, and the option focus ring were checked by eye in Storybook. Decisions worth knowing. The parts are Root, Trigger, Content, Item, and Group. Content renders the portal, the viewport, and a scroll button at either end itself, so a select takes no wrapper. The scroll buttons are there because Radix hides the viewport's own scrollbar, so without them a mouse user gets no sign that a long list scrolls, and the list is capped at 20rem so a long one scrolls instead of covering the page. The list opens below the trigger in Radix's popper position, at least as wide as the trigger, in place of Radix's default of overlapping the trigger with the picked item aligned to it, since that is what lines up with a form row. Group takes its heading as a label prop rather than a sixth Label part, so a group cannot exist without a name. Trigger takes placeholder and size, and fills its container like TextField's input, so the two line up in one grid column. Root takes name, required, and disabled beyond the ticket's value trio, since a select is a form control and RadioGroup already set that pattern; disabled lives on Root only, and Trigger omits its native disabled so there is one way to do it. Unlike Dialog and Tabs, Root owns the open state, for one reason: while the list is open Radix hides the rest of the page from assistive technology and holds focus inside the list, and axe's aria-hidden-focus rule flags the trigger as a focusable element inside aria-hidden. The trigger therefore carries tabindex -1 while its list is open, which is the remedy axe names and changes nothing a user can reach, and it lets WithGroups and WithDisabledItem end with the list open so axe audits the options, the groups, the highlighted fill, and a disabled option; ending every Story closed would have left the listbox unaudited, and the first cut switched the rule off for those two Stories instead, which the review rejected as the repo's first carve-out. A Consumer's own axe run with a Select open will still flag every other focusable element on their page, which is Radix's hideOthers behaviour and the same thing Dialog would show without axe's modal waiver. The highlighted option uses the primary fill, since the subtle background does not clear the 3:1 contrast a focus indicator needs, and the option under keyboard focus also carries the kit's 2px ring with offset, which survives forced colours where the fill does not. The visible label path is a bare label element the Consumer styles to match TextField, as the size Stories show; a Label part or a shared field label class is a candidate for a later ticket. The Stories query the scroll buttons and the viewport by class, the way Dialog's Story names its overlay, since neither carries a role. Kit-wide, the class-name join is now in eight Components, verify-build.mjs gained two more lines, and the portal Story helpers are copied from Dialog for the second time, so the shared helper, the derived build check, and shared Story helpers from tickets 06 and 09 are still open candidates.
