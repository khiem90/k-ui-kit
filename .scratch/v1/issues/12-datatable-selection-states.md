# 12: DataTable selection and states

**What to build:** A Consumer enables row selection and gets a Checkbox per row plus a select-all in the header, keyed by row id and usable controlled or uncontrolled. Loading and empty states replace a blank table with something a user understands.

**Blocked by:** 04 (Checkbox), 11 (DataTable with sorting and pagination)

**Status:** ready-for-agent

- [x] Props added: selectable, selectedIds, onSelectionChange, loading, emptyMessage
- [x] When selectable, a selection column renders a Checkbox in each row and a select-all Checkbox in the header that shows indeterminate when some rows are selected; each row checkbox has an accessible name derived from the row
- [x] Selection is keyed by getRowId and follows the value, defaultValue, onValueChange convention; select-all applies to the current page when paginated
- [x] Selected rows expose their state via a data attribute for styling
- [x] Loading renders a status region announced to assistive technology and keeps the header visible; empty renders the custom message in a single spanning cell
- [x] Stories for selectable, selectable and paginated, controlled selection, loading, and empty; a play function selects rows with Space, asserts the callback payload and the select-all indeterminate state, then uses select-all and asserts every row on the page is selected
- [x] axe passes on every Story; lint, typecheck, build pass

## Comments

2026-09-21: Checkbox landed in ticket 04 with a required, always-visible `label`. The row and select-all boxes here need an accessible name with no visible text, and the kit has no visually-hidden utility yet. Add a `hideLabel` prop to Checkbox in this ticket that keeps the label in the DOM for assistive technology and hides it visually.

2026-09-23: Implemented in 0a8f208 (selection, loading, empty, Checkbox hideLabel, six Stories, two changesets) and the code review fixes that follow it. Verified locally: lint, typecheck, and build pass, and 106 Story tests run in Chromium with axe, of which the 11 DataTable and 11 Checkbox Stories pass every time. The Select Long List Story failed in two of three full runs and passed alone, which is the timing-sensitive flake ticket 11 already flagged as a separate task. Selection, the selected-row tint in both Themes, the disabled select-all, loading, and empty were checked by eye in Storybook. Decisions worth knowing. The selection column renders outside the TanStack column model, so column definitions stay untouched and no column memo depends on `selectable`; when column groups make more than one header row, the selection header spans them. Each row's box is named "Select" plus the row's first text or number value, with "Select row N" (the position in `data`) as the fallback when a row has neither, so the docs tell the Consumer to put the identifying column first; a prop for naming rows is a candidate, but the spec's prop list excludes it from v1. Select-all is named "Select all rows on this page" only while there is more than one page, and it is disabled while the page has no rows, loading or empty, because a box that does nothing is a trap. Selection is an id list that follows the Checkbox pattern for controlled and uncontrolled state, mapped to TanStack's selection map; the callback gets the keys of the next map, which keeps insertion order for ids like `m-01` and numeric order for integer-like ids, so the docs promise no order. Ids that are not in `data` stay selected until the Consumer removes them, as TanStack does. `loading` withholds the rows and renders one cell spanning the table with a status region; on React 19 the text lands one render after the region mounts, through `useDeferredValue` with an initial value, because a live region announces a change to its text and not text it arrives with, and on React 18 it arrives with the region. A manual screen reader pass on that announcement is a candidate before release, as is announcing an empty result after loading, which the ticket did not ask for. `emptyMessage` defaults to "Nothing to show" so an empty table is never blank. A selected row carries `data-selected` and no `aria-selected`, which belongs to grids. Checkbox `hideLabel` sets `data-label-hidden` on the root and clips the label to a pixel positioned inside the root, so it never widens the DataTable's scroll container; the Dialog Stories carry an inline copy of the same technique, so a shared visually hidden utility is a candidate at the third use. Kit-wide, "Loading…", "Nothing to show", and the two select-all names join Previous and Next as English-only strings that a labels prop would cover, and the class-name join is now in ten Components.
