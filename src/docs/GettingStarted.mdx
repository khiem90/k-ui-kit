# Getting started

k-ui-kit is a small set of accessible React Components styled with plain CSS. They come in two Themes. Ridgeline, the default, is warm apricot and cream surfaces, Ember for actions, pill Buttons, and an arched Dialog. Noren, one attribute away, is Washi and Paper surfaces, Cat text, Lantern red for the main action, Tabs hung like cloth from a Cedar Rail, fields with a bottom edge only, and flat square Buttons. You get one package, one stylesheet that holds both Themes, an optional fonts stylesheet for each, and Tokens you override.

## Install

```bash
pnpm add k-ui-kit
```

React and React DOM 18 or later are peer dependencies. The kit has no other dependencies, so installing it adds one folder to `node_modules` and every line in it is the kit's own code. The package ships ESM with type declarations, so your bundler keeps only the Components you import and your editor completes their props.

## Import the stylesheet

Import it once, at the root of your app. In Next.js that is `app/layout.tsx`. In Vite it is `src/main.tsx`.

```tsx
import "k-ui-kit/styles.css";
```

That one file carries the Tokens of both Themes and every Component's styles. Class names and Tokens are prefixed `kui`, so nothing collides with your own CSS. It loads no font files.

## Add the fonts

Ridgeline uses three typefaces. Dialog titles are Fraunces. Labels, Buttons, tabs, and table headers are Josefin Sans. Everything else is Nunito Sans. All three ship inside the package. Import their stylesheet next to the main one:

```tsx
import "k-ui-kit/styles.css";
import "k-ui-kit/fonts.css";
```

Your bundler copies the woff2 files into your build, so you host nothing yourself. They come to 228 KB across seven files, but a browser only fetches the faces and character ranges a page draws. Each family's SIL Open Font License sits beside its files in the package. The faces use `font-display: swap`, so text shows in a fallback font until the file arrives.

Skip this import if your app already serves these families under the same names. The kit's Tokens name them, so your own font-face rules apply. If neither stylesheet provides them, the kit falls back to Georgia for Dialog titles and `system-ui` for the rest.

Noren has a fonts stylesheet of its own, `k-ui-kit/fonts/noren.css`, described under Themes below. Import the stylesheet for each Theme you use and no other, so a Ridgeline app never fetches a Noren face.

## Use a Component

```tsx
import { Button } from "k-ui-kit";

<Button variant="primary">Save</Button>;
```

Composite Components are namespaces of parts you assemble yourself:

```tsx
import { Button, Dialog } from "k-ui-kit";

<Dialog.Root>
  <Dialog.Trigger>
    <Button>Open</Button>
  </Dialog.Trigger>
  <Dialog.Content>
    <Dialog.Title>Confirm</Dialog.Title>
    <Dialog.Description>Are you sure?</Dialog.Description>
    <Dialog.Close />
  </Dialog.Content>
</Dialog.Root>;
```

Every Component works inside a React Server Component tree, namespaces included. The package draws its own client boundary, so you never add `"use client"` for it. One limit comes from React rather than the kit. A function cannot travel from the server to the browser, so props such as `onValueChange` or a DataTable `cell` renderer have to come from a client component.

## A form

TextField, Select, Checkbox, and Button share sizes and Tokens, so they line up with no extra CSS. Each one is a native form control, or submits like one, so a plain `form` works and so do form libraries. Select has no label of its own, so this one borrows the label Tokens to match TextField's.

```tsx
import type { CSSProperties } from "react";
import { Button, Checkbox, Select, TextField } from "k-ui-kit";

const labelStyle: CSSProperties = {
  font: "var(--kui-label-weight) 0.875rem/1.25rem var(--kui-font-label)",
  textTransform: "var(--kui-label-case)" as CSSProperties["textTransform"],
  letterSpacing: "var(--kui-label-tracking)",
};

export function SignUpForm() {
  return (
    <form
      action="/sign-up"
      method="post"
      style={{ display: "grid", gap: "var(--kui-space-4)", maxWidth: "24rem" }}
    >
      <TextField label="Email" name="email" type="email" autoComplete="email" required />
      <div style={{ display: "grid", gap: "var(--kui-space-2)" }}>
        <label htmlFor="plan" style={labelStyle}>
          Plan
        </label>
        <Select.Root name="plan" defaultValue="free">
          <Select.Trigger id="plan" />
          <Select.Content>
            <Select.Item value="free">Free</Select.Item>
            <Select.Item value="team">Team</Select.Item>
          </Select.Content>
        </Select.Root>
      </div>
      <Checkbox name="terms" label="I agree to the terms" required />
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

## Themes

Ridgeline applies as soon as the stylesheet loads. There is no attribute to set and no provider to wrap your app in. To switch the whole app to Noren, set one attribute on the html element:

```html
<html lang="en" data-theme="noren"></html>
```

Tokens inherit, so the attribute works on any ancestor, not only the root. A `section` with `data-theme="noren"` is a Noren section inside a Ridgeline page. A Dialog opened from inside it is Noren too, because the native dialog element stays a descendant of that section even while it sits in the top layer. Without the attribute nothing changes. Ridgeline is the default, and the Noren block adds a few kilobytes to the stylesheet you already import.

Noren uses two typefaces. Dialog titles are Shippori Mincho B1. Labels, Buttons, tabs, table headers, and everything else are Zen Kaku Gothic New. Both ship inside the package under a second stylesheet:

```tsx
import "k-ui-kit/styles.css";
import "k-ui-kit/fonts/noren.css";
```

They come to 55 KB across six files, the latin and latin-ext subsets of each face, under the same SIL Open Font License and `font-display: swap` as Ridgeline's. The latin-ext part needs a caveat. These families draw almost none of that range. Shippori Mincho B1 has the dotless i and the OE ligature, Zen Kaku Gothic New adds the Welsh circumflexes and the capital sharp s, and neither has Ł, ź, or the other Polish and Czech letters. Those letters, and any Japanese text, fall back to the next family in the stack. Skip the import if you already serve these families under the same names. Without it, Noren reaches Hiragino Mincho ProN or Yu Mincho for titles and Hiragino Sans or Yu Gothic for the rest on a Japanese system, and Georgia and `system-ui` anywhere else.

Both Themes have a light Color scheme only. Each block declares `color-scheme: light` and holds no dark values, so the kit looks the same whatever the operating system prefers. Switching your app to a dark Color scheme leaves the kit light, so there's nothing to wire up for it. `data-color-scheme` is reserved for a dark Color scheme, if one arrives.

This Storybook has a Theme menu in its toolbar, so you can view every Story under either Theme.

## Override Tokens

Every design value is a Token: colours, shadows, radii, border widths, fonts, label styling, spacing, and motion. Ridgeline declares them on `:root` and Noren on the element that carries `data-theme="noren"`. Set the ones you want in a plain `:root` rule. The kit wraps both of its selectors in `:where()`, which carries zero specificity, so your rule wins wherever it sits in the cascade.

```css
:root {
  --kui-primary: #2f6f5e;
  --kui-primary-hover: #1f4d41;
  --kui-focus-ring: #2f6f5e;
  --kui-radius-button: 12px;
}
```

Token names describe a role, not a colour, so `--kui-primary` means "the main action" under either Theme, and the override above changes the main action under both.

One case needs a second selector. A `:root` rule beats a Theme set on the html element, because your rule and the Theme block target the same element and yours wins on specificity. It does not reach inside a `data-theme` wrapper lower down the page, because the Noren block re-declares every Token on that wrapper and a declaration on the element beats one inherited from the root. To reach a themed subtree, target the wrapper as well:

```css
:root,
[data-theme] {
  --kui-primary: #2f6f5e;
}
```

An override applies to everything inside the element that sets it, so a rule on a `section` restyles one part of a page.

The kit checks the contrast of every pair it draws with each Theme's own values. When you change a colour, check its pairs yourself: text Tokens need 4.5:1 on the surfaces they sit on, and `--kui-border` and `--kui-focus-ring` need 3:1.

Ember is too faint on the Peach sky tint, and Lantern on Broth, so a control drawn on the tint uses its own pair of Tokens. A selected or hovered DataTable row draws its checked Checkbox in `--kui-primary-on-tint` and sets `--kui-focus-ring` to `--kui-focus-ring-on-tint`, so every control in the row, your own included, rings in that colour. The highlighted Select option draws its check in `--kui-primary-on-tint`. If you change `--kui-primary` or `--kui-focus-ring`, set these two as well.

## Every Token in both Themes

Three Tokens may hold four values, one per corner or side, the way the `border-radius` and `border-width` shorthands do: `--kui-radius-field`, `--kui-radius-tab`, and `--kui-border-width-field`. No other Token may. A width may be `0`, a shadow `none`, and a fill `transparent`, which is how a Theme switches off a part the other Theme draws, such as the Rail in Ridgeline or the Tabs track in Noren. Noren declares every Token below except `--kui-motion-duration`, which it inherits from Ridgeline so that the reduced-motion rule keeps the last word under both Themes.
